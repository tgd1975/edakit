DEF

Every derived value is the value its record derives – 1 codes.

Each engine decides one kind of relation; a finding's code is ENGINE.relation. Severities are the catalog's defaults – a project's domains may set others; a grade is a sub-case with its own severity, a topic the part of a code a domain switches on.

DEF.derive derived values within their window

warninginputs: warning

A part whose value a derivation record of the graph derives (derivations: the circuit language's derive, edakit block add --set) has a value inside the record's window, and every number the record used is what its source says now – the parts entry's field, the net's range, the catalog's table.

  • the window: one step of the series around the derived value (series_resistor, divider, rc), or [R_min, R_max] of a pull-up – the record names the rule, its inputs with their sources, the series' nearest value and what the chosen value predicts; the engine compares numbers only and never evaluates a rule
  • inputs: a record's input taken from a parts entry (C2297 values.vf_typ_v), a net's range (net LED_G1 v[1]) or a catalog table differs from what that source holds now
Why
A record says which value a rule of edakit's proposes from the entries and ranges; a part outside it was chosen otherwise, or the entries changed after the record was written.
What to do
Another part of the series inside the window (the candidates edakit block add --set names), or accept with the reason; for a record whose inputs changed edakit graph json --write (a .circuit source) or edakit graph derive --write (a JSON graph).
