# 12 Troubleshooting

Start with `edakit doctor`.

| Symptom | Cause | Fix |
|---|---|---|
| `easyeda_bridge_status`: not connected | no server ran yet, or EasyEDA was restarted | the first tool call starts the server; Auto-Connect connects within seconds. Otherwise *MCP Bridge → Connect*; with the patched bridge the menu may be missing – restart EasyEDA, Auto-Connect stays on |
| MCP tools missing in the session | the server did not start (Node not 24, npm failed) | `bash edakit/easyeda/mcp-server.sh doctor`; then `/mcp` → easyeda (only the user can reconnect) |
| port 49620 busy, "address in use" | an orphaned server (started through npx, or a crashed session) | `pgrep -af easyeda-mcp-pro`, `ss -ltnp \| grep 4962`, end the stale one (tell other sessions) |
| "timed out after 15000ms" or "expired (stale sweep)" | the server holding the port runs with the default 15 s | `edakit doctor` names the servers whose `BRIDGE_TIMEOUT_MS` differs, with their PIDs; end them (tell other sessions); they restart with `BRIDGE_TIMEOUT_MS=120000` from mcp-server.sh |
| DRC, pour fill or export hang; EasyEDA hardly busy | EasyEDA runs throttled because its window is covered | save, quit, start unthrottled (chapter 2.6); `edakit doctor` shows it |
| "bad option: --no-sandbox" when starting EasyEDA | `ELECTRON_RUN_AS_NODE` inherited from VS Code | `env -u ELECTRON_RUN_AS_NODE …` |
| every `DMT_*` call returns null | EasyEDA shows its start page (focus `tab_page1`) | open the project; edakit reopens it by its remembered UUID |
| "project is not open and EasyEDA does not list local projects" | edakit never saw the project open | open it once in EasyEDA |
| answers contain `[MaxDepth]`, DRC details empty; `edakit doctor`: "original extension" | original bridge extension | build and import the patched one (chapter 2.5): uninstall old, import, restart; `edakit doctor` says "patched extension" when the new one runs |
| `edakit doctor`: "bridge extension … against server …" or "method registry … differs" | the extension is of another easyeda-mcp-pro version than the pinned server | rebuild the patched extension from the pinned server (2.5) and import it |
| `PCB_Drc.check` returns null / undefined | the PCB tab counts as inactive | edakit switches to the start page and back; or click the PCB tab once |
| DRC: many "Connection Error" right after routing | DRC on the unsaved state after many API changes | `edakit route reload`, then DRC – reported 320 → 0 |
| DRC: "Netlist Error – Import Changes" | a part was freshly placed in the schematic | GEO.drc / `route drc` / `silk` say "EasyEDA waits for the import acknowledgement" (exit 3): open *Design → Import Changes* once in the GUI (shows "no changes") – the one click. They name differences instead: `edakit pcb parts --write` or `pcb nets --write` first |
| pour fill fails: "Cannot read properties of undefined (reading 'length')" | a free pad (tooling hole) is in the PCB | edakit removes tooling holes before filling; by hand: `edakit pcb tooling` after the fill |
| pour status `readback-mismatch` | harmless for the fill | look at the number of filled areas per layer; GEO.pour of the gate measures what the fill left |
| "focus lost" / "获取器件关联的所有引脚失败" (pins not readable) | another tab became active (a click, another script) | scripts get the tab back or abort; never run two EasyEDA jobs at once; claim EasyEDA |
| schematic texts come back after a reload | `SCH_PrimitiveText.delete` is not saved | edakit deletes through another primitive class (chapter 9.3) |
| renaming a schematic renamed another one | `modifySchematicName` acts on the active schematic | edakit activates first and checks every name; never delete on a mismatch |
| `edakit schematic check` suddenly reports a pin on two nets in the template | drift of unknown cause in a generated schematic | regenerate the template (`schematic create --save`) |
| `copy` refuses: "belongs to board" | the PCB is linked to the target | correct: use `edakit schematic layout`, which syncs in place |
| Freerouting leaves nets open | order dependence, crowded pads, rules | `route all` retries reshuffled; more passes; more room in the plan; a power plane; lower clearance only within EasyEDA's DRC |
| `route check`: a plane net open, its SMD pads on the other side in groups of their own | Freerouting connects no pad to a plane with a via | `fanout = true` on the plane in `[[pours]]` (7.5) |
| `route check` / GEO.spacing: "R22.2 (N3) – R37.1 (N2): 0.090 mm apart on TOP, below the clearance …" | two parts placed with their pads closer than the routing clearance; Freerouting cannot move a pad | move or turn one of them in `[place]` (fix it there if the auto-layout put it), then `pcb apply` and `route all` again |
| `route check` / GEO.spacing: "C2.2 (GND) – D1.2 (VIN): 0.300 mm apart on TOP, below the paste gap 0.400 mm" | SMD pads of two parts on an assembled side so close that the stencil leaves only a thin web between their prints – the paste can bridge in reflow | spread or turn one of them in `[place]`, then `pcb apply` and `route all` again; a pair close on purpose gets `accept` GEO.spacing with the reason |
| GEO.pour: "TOP: 47 % copper, largest copper-free circle Ø 9.7 mm at (-19.0, 111.7) mm" | EasyEDA dropped the pour pieces that touch no pad of the pour net, or the pour was not filled (again) after the last copper change | give the area a net that reaches it (a second pour net with `pour_regions`, or a pad or via of the pour net there), `route pours`, export and gate again; bare on purpose: accept the warning with its reason |
| GEO.pour: "TOP: 1 piece without pad, via or hole: 16.2 mm² around (10.5, 4.5) mm" | an island kept by a fill with islands (stitching) whose second fill did not run, or copper drawn by hand | connect it with a via or a track, or delete it; fill the pours again without islands |
| GEO.ring: "D31.1: 0.130 mm on TOP and BOTTOM (hole Ø 0.80 mm)" | the pad leaves less copper around the hole than JLCPCB's minimum ring (0.18 mm; a via 0.05 mm) – often a hole widened for the lead (GEO.hole) on a footprint whose pitch has no room for a larger pad | a larger pad or a smaller hole as far as GEO.hole allows; at a tight pitch another footprint or part; a ring the fab confirmed: `accept` GEO.ring on the part with the reason |
| GEO.spacing: "J1.2 – via at (3.00, 12.05): 0.398 mm apart, below 0.45 mm" | two plated holes closer edge to edge than JLCPCB's hole-to-hole spacing (0.45 mm with a component hole, 0.2 mm between vias) | move the via or the part, or a smaller hole where GEO.hole still passes |
| `route check` / GEO.spacing: "J1.1 (VIN) – via GND at (84.00, 9.70): 0.30 mm apart on BOTTOM, the solder side of J1, below hand_solder_keep_mm 0.5" | a via or a pad of another net next to a joint soldered by hand (`bom: false`), on the side the iron works on – at an SMD pad the side its part sits on ("the side D1 sits on") | a via: `route all` again – the DSN keeps vias away from the joints; a pad: move or turn one of the two parts in `[place]`; a pair close on purpose gets `accept` GEO.spacing with the reason |
| GEO.spacing (pad clearance, paste gap, hand-soldered joints): "… is not the PCB any more – … moved or changed since" | a part moved, turned or got another net after the last `route read` | `edakit route read` (or `route all`), then the gate again |
| `route dsn` stops: "… no room for a fanout via" | foreign pads, the edge, a hole or a keep-out around that pad | more room next to the pad in the plan, or a `windows` entry for its part in the keep-out |
| `pcb pour` stops: "pour_regions – the outlines … come from the routing" | `pour_regions` and no board file or SES yet | `edakit route all` (it pours at its end), or `route read` and `route route` first |
| "… its pour at (x, y) mm lies inside the pour of …" | a net's area is enclosed by another net's area on a shared layer – that outline would need a hole | the preview shows where: route so that the outer net does not enclose it, or leave the inner net's pour off that layer |
| `route check`: a pour-only net open in groups | tracks of other nets cut its pour into islands | the preview shows the computed pour and where it is cut: a wire keep-out on that layer where the tracks cut it, or more room between the pads there |
| Freerouting routes nothing in part of the board | concave outline as boundary | edakit uses a rectangle + keep-outs; if you write your own DSN, do the same |
| tracks appear where a wire keep-out should be | stale DSN | `route` writes the DSN fresh every time; `route check` uses the same config |
| "outline contains arcs" | outline drawn by hand with arcs | draw it with `edakit pcb apply` (arcs as point lists) |
| GEO.mark: "'+' at (-20.2, 92.5) mm: nearest pad D19.1 is cathode" | the footprint prints its "+" at the pad the parts entry calls the cathode – the print or the roles are wrong | compare the footprint with the datasheet: roles wrong → correct them in the parts entry; print wrong → put the anode's net on the pad with the "+" and give that pin the role `anode` (4.4), or another footprint; a decorative cross: `accept` GEO.mark on the nearest part |
| GEO.silk: "TOP: edakit's own print … off the solder-mask openings – 0.165 mm² in 1 spot: (19.1, 9.0) mm at C2.1" | a part or a via moved after `silk apply`, and a designator, text or artwork now lies on a pad | `edakit silk apply` after the last routing, then the gate again |
| GEO.silk: "silk_strings_main.json exists, silk_footprints_main/ does not" | `silk apply` of an older edakit: the gate cannot tell edakit's print from the footprints' | `edakit silk apply` once |
| GEO.silk: "R53: silkscreen on its solder-mask openings – JLCPCB clips it there" | the footprint's own frame or mark reaches over the pad's mask opening | correct the footprint, or accept the warning (JLCPCB clips the print there) |
| GEO.silk: "TOP: … mm² beyond it" | footprint print over the board edge (a connector's outline), or a frame drawn on the edge | correct the footprint or the drawing, or accept the warning; JLCPCB's DFM says "silkscreen outside board" |
| GEO.silk: "R21: no visible designator, no group label, not in [silk] unlabelled" | `silk apply` found no room for it ("without room"), or it was hidden | more room, a group label, or `[silk] unlabelled = { R21 = "…" }` with the reason |
| `silk apply` / `silk preview`: "R4: fixed designator on a pad (top) – 0.42 mm² of its box within 0.15 mm of a solder-mask opening" (or "beyond the printable board", "R4 / START: fixed designator on the text") | the spot in `[silk.place]` lies on a pad, over the edge or on another text – often after its part moved | move the row's `x`, `y` (plan mm) or turn it with `rot`, check with `edakit silk preview` offline, then `silk apply`; or drop the row and let `silk apply` find a spot |
| GEO.silk: "pcb.json without the designators" | an export by an older edakit, checked with `--offline` | `edakit fab` without `--offline` (or the gate with `--easyeda`) |
| GEO.silk: "BOTTOM (visible): D31 shows its designator – [silk] designators is top" | the part was placed again after `silk apply` (a swap, a footprint rebuilt) and came back with its designator shown | `edakit silk apply` (it hides the designators of `[silk] hide`), then the gate again; wanted there: `accept` GEO.silk on the part |
| GEO.silk: "TOP (visible): text 'TEST' at (15.0, 3.0) mm is neither the board label nor a [[silk.texts]] entry of this side" | a text placed by hand, or an old board label `silk apply` did not make | delete it, or put it into `[[silk.texts]]` with `side` = the visible side and run `silk apply` |
| SYNC.plan: "D1, R2: no row in hardware/boards/main.toml [place] (2 of 17 parts)" | the auto-layout placed them before edakit wrote its positions back, or parts came into the graph since | `edakit pcb apply`, then `edakit pcb autolayout`: it writes their rows (`auto = true`); a board already routed: `edakit pcb takeover --write` once, before any `pcb dump` – fixed rows where the parts stand (7.4) |
| `uv run …` exits 120 without output inside Claude Code | uv from snap cannot write to the file Claude Code hands it | `… 2>&1 \| cat` |
| a wait loop never ends | `pgrep -f` matches its own shell | wait for an end line or the PID (chapter 11.3) |
| EasyEDA crashed during a long run | V8 out of memory | restart, find the state, rerun the whole step; second crash: smaller blocks (start skill, section 4) |
| JLCPCB BOM tool: part missing | not in the assembly catalogue / no stock | gate check PARTS.stock asks the catalogue before the upload |
